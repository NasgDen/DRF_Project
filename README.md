# Домашняя работа - Django REST framework

## Описание
Проект написан на языке программирования Python с помощью фреймворка Django и инструмента Django REST framework.
Фреймворк Django - это набор инструментов, библиотек и правил, которые помогают разработчикам создавать приложения, упрощая и ускоряя процесс разработки. Фреймворк предоставляет структуру, внутри которой можно разрабатывать веб-приложения.
Django использует шаблон проектирования MTV (Model — Template — View).
Django REST framework (DRF) — это библиотека для Python, которая является надстройкой над веб-фреймворком Django и предназначена для создания RESTful API (интерфейсов прикладного программирования). Она предоставляет набор мощных и гибких инструментов, таких как сериализаторы, наборы представлений и аутентификация, которые значительно упрощают разработку и развертывание веб-сервисов, позволяя внешним приложениям взаимодействовать с Django-приложением.
В проекте используется интеграция с сервисом Stripe c помощью API. С документацией по сервису Stripe можно ознакомиться на официальном сайте сервиса [Stripe](https://docs.stripe.com/api) 

## Описание Моделей
Приложение lms - модуль контроллеров view.py:
1. Course - Описание полей модель - Курс.
2. Lesson - Описание полей модель - Урок.
3. Subscription - Описание полей модели - Подписка

Приложение users - модуль контроллеров view.py:
1. User - Описание полей модель - Пользователь.
2. Payments - Описание полей модель - Платежи.

## Описание Контроллеров
Приложение lms - модуль контроллеров view.py:
1. CourseViewSet - Класс реализует интерфейс для CRUD операция модели Course на основе ViewSet.
2. LessonCreateApiView - Класс реализует интерфейс для создания урока на основе generics.
3. LessonsListApiView - Класс реализует интерфейс для создания урока на основе generics.
4. LessonUpdateApiView - Класс реализует интерфейс для изменения урока на основе generics.
5. LessonRetrieveApiView - Класс реализует интерфейс для отображения одного урока на основе generics.
6. LessonsDestroyApiView - Класс реализует интерфейс для удаления урока на основе generics.

Приложение users - модуль контроллеров view.py:
1. UserViewSet - Класс реализует интерфейс для CRUD операция модели User на основе ViewSet.
2. PaymentsView - Класс реализует интерфейс для просмотра состояния оплаты на основе generics.
3. PaymentsCreate - Класс реализует интерфейс для создания платежа на основе generics.
4. PaymentsUpdate - Класс реализует интерфейс для проверки статуса платежа на основе generics.


## Установка

1. Клонируйте репозиторий:
```
git clone https://github.com/NasgDen/DRF_Project
```
2. В PyCharm установите менеджер проекта poetry.
3. В PyCharm устанавливаем все зависимости проекта из файла pyproject.toml
4. Переименуйте файл .env.sample в .env. Заполните файл конфигурации .env параметрами для подключения к базе данных.

## Запуск приложения с помощью Docker

1. Установите Docker по ссылке https://www.docker.com/products/docker-desktop/
2. Запустите установленный Docker.
3. В файле .env установите следующие значения:
    ```
    HOST=db
    PORT=5432
    CELERY_BROKER_URL=redis://redis_proj:6379/0
    CELERY_RESULT_BACKEND=redis://redis_proj:6379/0
    ```
    Остальные значения установите в соответствии вашей конфигурации.
4. Для создания многоконтейнерного приложения используйте Docker Compose.
5. Для сборки контейнеров и последующего запуска всех сервисов выполните команду:
    ```
    docker compose up --build
    ```
6. Для проверки запущенных контейнеров выполните команду:
    ```
    docker ps
    ```
7. Сервер запущен по адресу 127.0.0.1:8000 (localhost:8000)
8. Для просмотра документации по приложению в браузере введите следующий адрес:
    ```
    127.0.0.1:8000/swagger-ui/
    
    ```
    или
    ```
    127.0.0.1:8000/redoc/
    ```
9. Для остановки всех запущенных сервисов выполните команду:
    ```
    docker compose down
    ```

## CI/CD (Continuous Integration/Continuous Delivery)

Это методология DevOps, которая автоматизирует процессы сборки, тестирования и развертывания кода для ускорения и повышения надежности разработки программного обеспечения.
CI/CD описан в файле ci.yml (папка .github/workflows).
При каждом push и pull-request на git hub репозиторий происходит проверка кода линтером flake8, далее происходит блок тестирования кода. 
После успешных проверок происходит автоматическое развертывание и запуск приложения на сервере.
Все переменные проекта должны быть указаны в git hub secrets.

2. Сервер запускается по адресу: 127.0.0.1:8000
